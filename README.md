## 这是什么

本仓库保存了两份内容：

1. **博客全文离线镜像** —— 2009–2021 年全部博文的静态 HTML，含标签索引、年份归档、样式与图片，可在完全离线状态下浏览。
2. **电子图书馆** —— 11 个分类、2189 个电子书文件，格式涵盖 PDF / EPUB / MOBI / TXT / CHM / AZW3 / DJVU。

内容来自原作者公开发布的备份与 BT Sync（Resilio Sync）共享。**这是一份冻结归档**：最后一期正文为 2021 年 4 月，此后不再有增量。

### BT Sync 密钥（重要说明）

**这些密钥是原作者公开发布的只读共享密钥，不是机密信息** —— 同一批密钥同样出现在公开的 `__所有电子书的清单__.html` 中。它们的价值在于**灾备**：即使本仓库或其 GitHub 镜像消失，凭这些密钥仍可从 P2P 网络重新同步全部内容。

## 打包产物（CHM / EPUB）

`blog/make/` 下是原作者的 HTML → CHM / EPUB 打包工具链。**使用前请务必读这一节。**

### ⚠️ 配置是预生成产物，生成器不在本仓库

仓库里只有 2 个 Python 脚本和 2 个 WSF 脚本，都是**打包**步骤：

| 文件 | 作用 |
|---|---|
| `chm/make-chm.py` / `chm/make-chm.wsf` | 调用 `hhc.exe` 编译 CHM |
| `epub/make-epub.py` / `epub/make-epub.wsf` | 把目录打包成 EPUB |

而体积最大、承载全部结构信息的三个文件 —— `chm/conf/program-think.hhp`（815 KB）、`chm/conf/program-think.hhc`、`epub/conf/program-think.opf`（2.0 MB）—— 都是**2021-04-13 的预生成产物，生成它们的脚本不在本仓库内**。

**后果：内容一旦变化，目录结构、spine 顺序、manifest 都无法重新生成。这套链路是「可重复打包，不可重复生成」。**

### CHM 分支：需要 Windows

- `make-chm.py` 在非 Windows 平台会改走 `wine hhc.exe`，**macOS / Linux 上若无 wine 必然失败**；
- 依赖的 `chm/hhc.exe`、`chm/hha.dll` 是 1999 年的 Microsoft HTML Help Workshop 二进制（32 位 PE），**仅作历史留存，不要当作可靠的构建依赖**；
- CHM 格式本身只有 Windows 原生可读，微软早已停止维护。

**结论：CHM 是归档物，不是可构建目标。**

### EPUB 分支：可运行，但产出物不符合 OCF 规范

`make-epub.py` 用 Python 标准库即可运行（无第三方依赖），但实测产出存在规范级问题：

- `mimetype` **不是 zip 的第一条**且被 DEFLATE 压缩 —— OCF 规范要求它必须是首条且以 STORED 方式存储；
- 打包时未做排除，`.DS_Store` 等垃圾文件会一并进入产物；
- 博客页面本身并非全部良构 XML，而 manifest 中声明为 `application/xhtml+xml`。

严格实现的阅读器可能拒绝加载。**如需正式产物，建议改用成熟工具（如 `pandoc`、`ebook-convert`）重新生成，而不是修这套脚本。**

### 编码提示

同一工具链内混用两种编码：`.hhp` / `.hhc` 是 **GBK/CP936**（在 UTF-8 环境下查看会乱码），`.opf` / `.ncx` 是 **UTF-8**。

## 命名规范

电子书文件名基本遵循统一模式，可被脚本解析：

```
作者：中文书名@年份 (版本说明).扩展名
Author：English Title@Year (edition).ext
```

⚠️ 注意两种历史遗留形态，写脚本时请勿踩坑：

1. **约 64 个目录名带文件扩展名**，例如 `…/理查德·史蒂文斯：UNIX 网络编程 (共2卷 扫描版).pdf/第1卷 ….pdf` —— 同一层级既有 `X.pdf` 文件又有 `X.pdf/` 目录。**任何「按扩展名筛选文件」的脚本都会误判**，务必用 `-type f` 限定。
2. **标签页文件名是 UTF-8 字节的十六进制**（如 `tags/E694BFE6B2BB.html` 对应「政治」）。这是刻意设计：它同时解决了跨文件系统编码差异、URL 安全、以及标签名中的 `/` 被当作路径分隔符三个问题。显示名由索引页承担。

## 克隆与恢复

**只想拿内容，不想拉 15 GiB 的 Git 历史：**

```bash
# 浅克隆：只取最新快照
git clone --depth 1 https://github.com/4choor3/4choor3-programthink-Backup.git
```

**想用更轻的方式重建整个书库：** 见 `__所有电子书目录的密钥__.txt`，用 Resilio Sync 按密钥同步，无需经过 Git。

**推送注意：** 本仓库单次推送体积较大，本地 `.git/config` 中已设 `http.postBuffer=2147483648`（2 GB）。换机器推送时该设置不会随仓库带走，需重新配置，否则可能遇到 443 超时。
